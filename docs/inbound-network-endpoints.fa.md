# شبکه و Host در ساخت اینباند

این تغییر، ادامهٔ [فرم یکپارچهٔ اتصال و دارک‌سواپ](inbound-editor-unified-flow.fa.md)
است. شبکهٔ XHTTP، تنظیمات مشتری REALITY و اطلاعات مستقل هر Host به چرخهٔ
ساخت، بازبینی، ذخیره و ویرایش پلن اضافه می‌شوند. پشتیبانی در renderer و codec
نیز با Core ثابت پروژه آزمایش می‌شود. فعال‌سازی پلن و انتشار اشتراک همچنان
مرز اجرایی جدا دارند؛ ثبت آدرس عمومی، NAT یا تونل خارجی ایجاد نمی‌کند.

## جای کنترل‌ها

| بخش | تنظیمات |
| --- | --- |
| اتصال / شبکه | TCP، gRPC یا XHTTP؛ گزینه‌های مختص همان شبکه در همان محل. |
| اتصال / امنیت | تنظیمات REALITY، شناسه‌های کوتاه و پیش‌فرض‌های مشتری؛ کلید عمومی فقط پس از ساخت واقعی نمایش داده می‌شود. |
| دارک‌سواپ | انتخاب نود، Listen IP، روشن/خاموش مستقل Direct و Tunnel، پورت شنود و Hostهای هر مسیر، و مسیر اختیاری Swap. |
| پیشرفته | Sniffing و Fallback با محدودیت‌های ثبت‌شده در سند تنظیمات ترافیک. |
| بازبینی | مقادیر فرم و خلاصهٔ اتصال محاسبه‌شده در سرور؛ پورت عمومی و شنود جدا مشخص می‌شوند. |

تنظیمات Host داخل کارت همان نود و مسیر است. فهرست ساده و ردیف‌های کامل
Host هم‌زمان دو منبع قابل ویرایش نیستند. تبدیل به حالت کامل، آدرس‌های فعلی
را حفظ می‌کند. بازگشت به فهرست ساده با تأیید حذف metadata انجام می‌شود.
خاموش و روشن کردن یک مسیر هنگام ویرایش، پیش‌نویس محلی را حفظ می‌کند؛
در درخواست ذخیرهٔ مسیر خاموش، پورت صفر و Host/endpoint خالی ارسال می‌شود.

## شبکه و گزینه‌های مشتری

### XHTTP

`profile.transport = "xhttp"` و `profile.options.xhttp` دارای این فیلدهاست:

| فیلد | قرارداد |
| --- | --- |
| `path` | مسیر شروع‌شده با `/`، حداکثر ۲۰۴۸ بایت؛ بدون authority، query، fragment، فاصله یا نویسهٔ کنترل. خالی یعنی پیش‌فرض Core. |
| `host` | نام DNS با نویسه‌های ASCII یا IPv4، بدون پورت، bracket یا colon؛ خالی مجاز است. |
| `mode` | `auto`، `packet-up`، `stream-up` یا `stream-one`؛ خالی یعنی پیش‌فرض Core. |
| `x_padding_bytes` | عدد یا بازهٔ صحیح مرتب مانند `256` یا `200-400`؛ حداقل ۱ و حداکثر ۶۵۵۳۶. JSON آزاد پذیرفته نمی‌شود. |

Host دارای پورت از این قرارداد حذف شده، چون Core ثابت هنگام بررسی Host
پورت درخواست را حذف می‌کند و آن را با مقدار تنظیم‌شده مقایسه می‌کند.
gRPC همچنان authority با پورت را می‌پذیرد. این دو اعتبارسنجی یکسان نیستند.

### REALITY سمت مشتری

`profile.options.client` شامل `fingerprint` و `spider_x` است. این مقدارها
وارد تنظیمات REALITY سمت سرور نمی‌شوند. پیش‌فرض مؤثر Chrome و `/` است.
انتخاب‌های fingerprint: `chrome`, `firefox`, `safari`, `ios`, `android`,
`edge`, `360`, `qq`, `random`, `randomized`.

SpiderX یک مسیر مطلق محلی با query معتبر اختیاری و حداکثر ۲۰۴۸ بایت است.
authority، fragment، فاصله و نویسهٔ کنترل مجاز نیست. پارامترهای `p`, `c`,
`t`, `i`, `r` چون در Core تنظیمات crawler هستند، تا اضافه‌شدن قرارداد عددی
محدود برای آن‌ها پذیرفته نمی‌شوند.

در codec، خروجی gRPC اکنون `authority` و `mode=gun|multi` را منتقل می‌کند.
خروجی XHTTP شامل `path`, `host`, `mode` و padding تایپ‌شده در `extra` است.
fingerprint و SpiderX از metadata صریح مشتری می‌آیند؛ از کانفیگ سرور
حدس زده نمی‌شوند. این پشتیبانی codec، به معنی فعال‌شدن انتشار عمومی نیست.

## Host مستقل هر مسیر

هر نود می‌تواند `direct_endpoints` و `tunnel_endpoints` داشته باشد؛
حداکثر ۶۴ ردیف برای هر مسیر.

| فیلد | رفتار |
| --- | --- |
| `address` | DNS، IPv4 یا IPv6 بدون bracket/port؛ DNS کوچک‌حرف و IP استاندارد ذخیره می‌شود. |
| `port` | پورت عمومی ۱ تا ۶۵۵۳۵؛ صفر یعنی استفاده از پورت شنود همان مسیر. |
| `label` | نام اختیاری تا ۱۲۸ نویسهٔ Unicode، بدون نویسهٔ کنترل. |
| `enabled` | ردیف خاموش ذخیره می‌شود ولی در فهرست Hostهای آماده قرار نمی‌گیرد. |
| `sni` | خالی یعنی اولین SNI پروفایل؛ مقدار مستقل باید دقیقاً یکی از Server Nameهای پروفایل باشد. |
| `fingerprint` | خالی یعنی ارث‌بری از پیش‌فرض مشتری پروفایل. |
| `spider_x` | خالی یعنی ارث‌بری از پیش‌فرض مشتری پروفایل. |

برای نمونه می‌توان listener را روی ۱۰۴۴۳ و Host عمومی را روی ۴۴۳ ثبت کرد.
پورت شنود طبق سیاست فعلی ۱۰۲۴ تا ۶۵۵۳۵ است؛ ۲۰۸۷، ۸۴۴۳ و ۲۴۴۴۳ رزرو هستند.
تکرار یک آدرس با پورت یا گزینه‌های مشتری متفاوت مجاز است؛ تکرار دقیق هویت
مؤثر اتصال، حتی میان ردیف‌های خاموش، خطا دارد.

`direct_hosts` و `tunnel_hosts` برای سازگاری حفظ می‌شوند، ولی در حالت کامل
باید دقیقاً آدرس‌های یکتای endpointهای روشن و به همان ترتیب باشند. سرور
ناهماهنگی این دو نمایش را رد می‌کند. فهرست Host ساده نیز اکنون IPv6 را
می‌پذیرد. مقدار `null` یا حذف فیلد endpoint، درخواست حذف metadata نیست؛
حذف آگاهانه با آرایهٔ خالی بیان می‌شود.

## بازبینی، خطا و فهرست نودها

پاسخ Preview یک فهرست `endpoints` محاسبه‌شده در سرور دارد: نود و مسیر،
آدرس، پورت عمومی و شنود، label، روشن/خاموش، SNI، transport و گزینه‌های
مؤثر مشتری. این خلاصه UUID، کلید خصوصی یا URI مشتری ندارد. مرورگر پیش از
اجازهٔ ذخیره، آن را با تمام مقادیر درخواست تطبیق می‌دهد؛ خلاصهٔ دستکاری‌شده،
ناقص یا دارای فیلد ناشناخته پذیرفته نمی‌شود.

خطاهای پروفایل، پورت و ردیف Host به همان فیلد برمی‌گردند. برخورد listener
واسط، علاوه بر نود فیزیکی، نود مقصد صاحب آن مسیر را دارد؛ بنابراین فرم کارت
مربوط را باز می‌کند. خطاهای قدیمی‌تر API همچنان نگاشت سازگار دارند.

فهرست پلن‌ها، payload رمز‌شده را احراز و از آن `node_ids` را استخراج می‌کند:
نودهای مقصد و واسط‌های Swap روشن، مرتب و بدون تکرار. فهرست UI نودهای پلن
را از نودهای تخصیص اجرایی تفکیک می‌کند. نمایش و فیلتر یک واسط، تخصیص جدید
یا مقصد جدید در ویرایشگر نمی‌سازد.

## حفظ داده و سازگاری

- پروفایل‌های قدیمی v1/v2/v3 خوانده می‌شوند. XHTTP یا گزینه‌های جدید مشتری
  با envelope احراز‌شدهٔ v4 ذخیره می‌شوند تا نسخهٔ قدیمی آن‌ها را با حذف
  بی‌صدای فیلدهای ناشناخته بازنویسی نکند.
- پلن‌ها و رسیدهای دارای metadata جدید، envelope v2 مستقل دارند.
  خواندن JSON ذخیره‌شده، فیلد ناشناخته، کلید تکراری و دادهٔ اضافی را رد می‌کند.
- پاک‌کردن تنظیمات جدید از رکورد فعلی، رسیدهای قدیمیِ آن را بازنویسی نمی‌کند.
  بررسی امکان بازگشت نسخه باید هر سه محل پروفایل، پلن و رسید را پس از توقف
  نویسنده بررسی کند؛ صرفاً سازگار بودن رکورد فعلی کافی نیست.
- ویرایشگر قدیمی اجازه ندارد بخش موجود XHTTP، client یا endpoint را با
  حذف فیلد پاک کند. پاک‌کردن باید صریح باشد: object خالی یا آرایهٔ خالی.
- تغییر transport کلید REALITY یا شناسهٔ اینباند را عوض نمی‌کند. revision،
  تطبیق کامل رسید، ثبت رویداد و تکرار امن درخواست حفظ می‌شوند.
- API عمومی ساخت اینباند هم سقف فعلی ۲۵۶ رکورد را به‌صورت اتمی رعایت می‌کند.
  رکورد بایگانی‌شده هنوز در این سقف حساب می‌شود؛ pagination تاریخچه در این
  تغییر پیاده نشده است.

## شواهد و مرز باقی‌مانده

تست‌های backend ذخیره/بازخوانی رمز‌شده، clear صریح، IPv6، پورت عمومی،
برخورد listener، هدف‌گیری دقیق خطا، payload دستکاری‌شده و حفظ هویت را پوشش
می‌دهند. آزمون واقعی Core نسخهٔ ثابت v26.9.9 هر چهار حالت XHTTP و هر دو
حالت gRPC را از URI خروجی تا دریافت payload محدود روی loopback اجرا می‌کند؛
Path، Host و Padding اشتباه نباید به origin برسند. پیکربندی Direct/Tunnel
و Swap با XHTTP نیز در حالت offline به خود Core داده می‌شود.

آزمون مرورگر واقعی با UI کامپایل‌شده، API احرازشده و SQLite موقت، چرخهٔ
TCP → gRPC → XHTTP را اجرا و هویت، revision، metadata، Host خاموش و
snapshotهای نامرتبط مشتری و تخصیص را بررسی می‌کند. تست‌های مرورگرِ پاسخ‌های
کنترل‌شده نیز صحت Preview/receipt، نمایش موبایل و انتقال focus را پوشش می‌دهند.
نتیجهٔ اجرای هر مجموعه و نصب LAB در PR همین تغییر ثبت می‌شود.

قابلیت‌های جدید فقط در authoring پلن اعلام می‌شوند؛ `runtime_apply=false`
باقی است. قرارداد فعلی حسابداری و انتشار اشتراک گسترش نمی‌یابد.
پشتیبانی TLS، WebSocket و HTTP Upgrade در
[مرحلهٔ بعدی شبکه و گواهی](inbound-tls-transports.fa.md) تکمیل شده است.
mKCP و پروتکل‌های دیگر، مسیر عمومی فعال‌سازی پلن و تحویل عمومی اشتراک
همچنان کار جدا دارند. فیلد ALPN مستقل و JSON آزاد برای ایجاد ظاهریِ
قابلیت اضافه نشده‌اند.
