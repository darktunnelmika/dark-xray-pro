# سامان‌دهی مرحله‌ای پنل و تکمیل قابلیت‌ها

تاریخ: **۲۳ اکتبر ۲۰۲۶**. این برنامه، تصمیم مالک برای مرتب‌کردن پنل و تکمیل
قابلیت‌ها **یکی‌یکی** را ثبت می‌کند. وضعیت فعلی: **پایهٔ UX اینباندها پیاده‌سازی
شد؛ build و هر ۲۲۹ سناریوی مرورگر روی نسخهٔ نهایی این مرحله موفق بودند.** وضعیت
عملکردی هر حوزه همچنان در [ماتریس دامنه و قابلیت‌ها](release/feature-scope-and-status.fa.md)
تعیین می‌شود؛ تغییر چیدمان، وضعیت runtime یا آمادگی کل محصول را ارتقا نمی‌دهد.

## چیدمان و مسیرهای قابل کشف

ناوبری فشرده و گروه‌بندی‌شده است؛ هر گروه باز و بسته می‌شود و مقصد فعال مشخص
می‌ماند. نمایش مقصدها به نقش و مجوز حساب وابسته است. این سازمان‌دهی در
[پوسته](../web/src/App.tsx) و [مسیرهای پنل](../web/src/navigation.ts) انجام می‌شود.

| گروه | مقصدها |
| --- | --- |
| زیرساخت | داشبورد، نودها، اینباندها، Dark Swap |
| مشتری و فروش | کلاینت‌ها، گروه‌ها، نمایندگان، کاتالوگ، امور مالی، تلگرام |
| پشتیبان‌گیری و بازیابی | Backup، Dark Restore |
| حساب و تنظیمات | حساب من، تنظیمات |

**مقصدهای Restore، Telegram و Backup فقط صفحهٔ معرفی وضعیت و کارهای باقی‌مانده‌اند.**
وجود مسیر یا منوی آن‌ها به معنی پیاده‌شدن importer، ربات، Mini App یا بکاپ نیست.
[صفحهٔ وضعیت ماژول‌ها](../web/src/ModuleStatus.tsx) عملیاتی را شبیه‌سازی نمی‌کند؛
وضعیت F13 تا F15 به‌علت اضافه‌شدن این مقصدها تغییر نمی‌کند.

## مرحلهٔ جاری: پایهٔ UX اینباندها

الگوی کار، فهرست و مدیریت جزئیات مشابه سنایی است، با استفاده از API و ذخیره‌سازی
واقعی PRO. خروجی پذیرفته‌شدهٔ این مرحله در
[NativeInbounds](../web/src/NativeInbounds.tsx) و
[ویرایشگر مسیر](../web/src/NativeRouteDraftEditor.tsx) چنین است:

- فهرست واقعی اینباندها با جست‌وجو، فیلتر و صفحه‌بندی ۲۰ ردیفی روی snapshot موجود؛
  وضعیت، بارگذاری، خالی و خطا مشخص‌اند. فیلترهای موبایل در حالت پیش‌فرض بسته‌اند.
- ساخت اینباند در پنجرهٔ مجزا، جزئیات در تب‌های «خلاصه»، «مسیرها»، «کلاینت‌ها»
  و «تاریخچه»؛ تب‌زدن، ویرایش ذخیره‌نشده را نگه می‌دارد. خروج از جزئیات،
  انتخاب صفحهٔ دیگر و Back مرورگر برای کنارگذاشتن ویرایش هشدار دارند.
- کپی پروفایل عمومی، اینباند جدید با شناسه، Short ID و کلید تازه می‌سازد؛
  کلاینت‌ها و مقصد نود را کپی نمی‌کند. پنجرهٔ تنظیم مقصد نود به API موجود متصل است.
- بررسی‌های فنی LAB در بخش بستهٔ پیش‌فرض قرار دارند و برای بررسی باز می‌شوند؛
  درخواست نامطمئن هنگام بستن بخش، حتی بدون sessionStorage، حفظ می‌شود.
  وضعیت مسدود یا تأییدنشده همچنان روشن است و گیت runtime تغییر نکرده است.
- مقصد مستقل Dark Swap به همان پیش‌نویس واقعی و ذخیره‌شدهٔ مسیر متصل است.
  Direct/Tunnel/Swap همچنان نیازمند پذیرش مستقل اجرا، تحویل و حسابداری‌اند؛
  ذخیرهٔ پیش‌نویس یا نتیجهٔ readiness، تونل فعال محسوب نمی‌شود.

در همین مرحله، وابستگی نادرست فهرست کلاینت نماینده به مجوز مالی و حذف‌شدن
کاما هنگام تایپ چند Host اصلاح شد. سطح دسترسی API افزایش نمی‌یابد.
پیش‌نویس مسیر از قبل ذخیره‌سازی واقعی دارد؛ حدود آن در
[قرارداد route draft](inbounds-p0e-native-route-drafts.md) ثبت شده است.

## ترتیب تکمیل محصول

هر ردیف پس از بررسی خروجی مرحلهٔ قبلی پیش می‌رود. زیرقابلیت‌های یک ردیف نیز
جداگانه پیاده و پذیرفته می‌شوند؛ چند منوی نیمه‌کاره جای پایان یک جریان را نمی‌گیرد.

| ترتیب | حوزه | نتیجهٔ لازم برای پایان کار همان حوزه |
| --- | --- | --- |
| ۱ — پذیرفته‌شده در دامنهٔ UX | پایهٔ UX اینباندها | فهرست، ساخت، جزئیات، مقصد نود و مسیرهای ذخیره‌شده قابل استفاده؛ حفظ ویرایش، فارسی/انگلیسی، روشن/تیره و موبایل در جریان واقعی مرورگر بررسی شوند. این پذیرش محدود به UX است. |
| ۲ — بعدی | پروتکل‌ها و Hosts؛ چرخهٔ نود؛ اشتراک عمومی | پشتیبانی و پذیرش پروتکل/transportهای لازم، مدیریت Hosts و چند IP؛ چرخهٔ امن نود و تعویض با حفظ وابستگی‌ها؛ انتشار و تحویل عمومی اشتراک با اثبات مسیر، تمدید اعتبار مسیر و بازیابی. حدود N18/N19 محفوظ بمانند. |
| ۳ | Tunnel و Dark Swap با حسابداری | اجرای واقعی مسیر چندنودی، Apply/ACK، حفظ upstream، مصرف یکتای مقصد، آمار قابل‌انتساب و رفتار قطع، retry و rollback؛ پیش‌نویس به‌تنهایی کافی نیست. |
| ۴ | Import/Export بومی و سیاست مشتری | حفظ هویت و روابط و مصرف در ورود/خروج داده؛ شروع مدت از اولین اتصال؛ اعمال واقعی IP Limit/HWID و اصل IP معتبر پشت تونل. |
| ۵ | Backup و Dark Restore | بکاپ کاملِ مخصوص مالک، شامل دادهٔ نمایندگان و ربات‌ها، با آرشیو کم‌حجم، زمان‌بندی و بازیابی بررسی‌شده؛ importer مستقل Restore با dry-run، namespace جدا، حفظ UUID/token/link/تاریخچه/گروه/نماینده، آرشیو منقضی‌ها و ادامه یا بازگشت پس از شکست. |
| ۶ | فروش V10c | سفارش، پرداخت، خرید/تمدید و ساخت اتمیک مشتری متصل به محصول؛ wallet و بازیابی شکست بدون debit یا تحویل تکراری. انتشار کاتالوگ پایان این مرحله نیست. |
| ۷ | Bot و Mini App | جریان مشتری/مالک/نماینده روی همان داده و مجوزها؛ فروش، تمدید، تحویل و پشتیبانی؛ ادمین‌های ربات نماینده و پیام همگانی با پیش‌نمایش، تأیید، صف، توقف و گزارش. |
| ۸ | گزارش، تنظیمات، امنیت و کارایی یکپارچه | گزارش و هشدار/لاگ عملیاتی، تنظیمات و نگهداری منسجم، گیت‌های امنیت باقی‌مانده و پذیرش اندازه‌گیری‌شدهٔ فشار، قطعی، reboot و بازیابی برای نسخهٔ واحد محصول. |

## معیار پایان هر ماژول

ادعای «کامل» باید برای همان نسخه و دامنه، شواهد این موارد را داشته باشد:

| معیار | شاهد لازم |
| --- | --- |
| رابط واقعی | جریان کار قابل انجام، وضعیت روشن و نتیجهٔ قابل مشاهده؛ منو یا صفحهٔ معرفی کافی نیست. |
| پایداری داده | ذخیره و بارگذاری دوباره، حفظ هویت و تاریخچه و نتیجهٔ درست تکرار درخواست. |
| مجوز محدود به حساب | کنترل سمت API برای مالک/نماینده/مشتریِ مربوط و منع دسترسی به دادهٔ حساب دیگر؛ پنهان‌کردن دکمه کافی نیست. |
| اجرا و تحویل، در صورت کاربرد | اثبات runtime، مسیر مصرف‌کننده، تحویل اشتراک/پیام/پرداخت یا بازیابی مورد نیاز همان قابلیت؛ ذخیرهٔ تنظیمات جای آن را نمی‌گیرد. |
| خطا و تلاش دوباره | خطای قابل فهم، retry بدون دوباره‌کاری مالی/هویتی و recovery یا rollback متناسب با عمل. |
| جریان مرورگر | آزمون موفق و ناموفق با نقش‌های مربوط، و بررسی فارسی/RTL، موبایل و تم‌ها برای مسیرهای تغییرکرده. تعداد تست به‌تنهایی معیار تکمیل نیست. |

## شواهد پذیرش این مرحله

- `npm run build`: TypeScript سخت‌گیرانه و build تولیدی موفق؛ هشدار قبلی حجم chunk
  همچنان باقی است و به معنی شکست build نیست.
- مجموعهٔ کامل Chromium: **۲۲۹ موفق، بدون شکست**؛ ۱۳ سناریوی جدید علاوه بر
  تطبیق مسیرهای آزمون قبلی. پوشش شامل کپی امن پروفایل، فیلتر/صفحه‌بندی، فوکوس
  پنجره، حالت RTL، حفظ ویرایش، ورود مجدد به لینک جزئیات، مجوز مالی نماینده،
  استقلال وضعیت canary از جست‌وجوی کلاینت و حفظ retry دقیق است.
- بازبینی تصویری دسکتاپ روشن/تیره و موبایل فارسی ۳۲۰ پیکسل با دادهٔ مصنوعی:
  بدون سرریز افقی، خطای مرورگر یا تماس خارجی. کارت اول اینباند در نمای نهایی
  موبایل کامل دیده می‌شود و دکمه‌های بررسی‌شده حداقل ۴۴ پیکسل‌اند.

این پذیرش محدود به همین تغییرات رابط است؛ انتشار عملیاتی یا پذیرش کامل runtime
محسوب نمی‌شود. شواهد قبلی N17، N18 و N19 اعتبار خود را در دامنهٔ ثبت‌شده حفظ
می‌کنند؛ این برنامه آن‌ها را «انجام‌نشده» اعلام نمی‌کند.

## مرز دامنه

WARP و ضدتبلیغ در هیچ مرحله‌ای اضافه نمی‌شوند. این برنامه توسعهٔ محصول با
دادهٔ مصنوعی است و نصب عملیاتی، انتقال دادهٔ واقعی قدیمی، تغییر Bot/token،
دامنه/پورت یا دست‌زدن به HUB و نودهای عملیاتی را شامل نمی‌شود. ساخت ابزار
Dark Restore بخشی از محصول است؛ اجرای مهاجرت واقعی قدیمی همچنان جدا و به‌تعویق‌افتاده
است و انجام‌نشدن آن، با نبود importer محصول یکسان نیست.
