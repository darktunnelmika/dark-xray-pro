# تنظیمات Sniffing و Fallback در ویرایشگر اینباند

این مرحله، بخش «پیشرفته» در ویرایشگر یکپارچهٔ ساخت اینباند را به تنظیمات
واقعی پروفایل و تولید کانفیگ متصل می‌کند. محدودهٔ فعلی **طرح ساختِ متوقف**
است؛ قابلیت‌های API با `profile_traffic_options_scope: "creation_plan"`
همین محدوده را اعلام می‌کنند.

## رفتار فرم و ذخیره

- Sniffing دارای کلید روشن/خاموش، انتخاب HTTP/TLS/QUIC/FakeDNS، گزینه‌های
  `routeOnly` و `metadataOnly` و استثناهای دامنه و IP است.
- خاموش‌کردن Sniffing، تنظیمات فرعی آن را نگه می‌دارد. عمل جداگانهٔ
  «بازنشانی تنظیمات Sniffing» برای پاک‌کردن کامل آن است.
- Fallbackها ردیف‌های قابل افزودن/حذف با Path، مقصد و Xver دارند.
  تغییر انتقال به gRPC، ردیف‌های موجود را بی‌صدا حذف نمی‌کند؛ مالک باید
  ناسازگاری را برطرف کند.
- داده‌ها در ایجاد، بازکردن مجدد، ویرایش و کپی پروفایل به طرح تازه حفظ
  می‌شوند. بازبینی و پاسخ ذخیره باید با تنظیمات ارسال‌شده تطابق کامل داشته باشند.
- خطای هر بخش، کاربر را به تب «پیشرفته» و کنترل مربوط هدایت می‌کند.
- listenerهای مقصد Direct، Tunnel و Dark Swap همان تنظیمات را دریافت
  می‌کنند؛ listener واسط Swap این گزینه‌ها یا حساب مشتری مقصد را نمی‌گیرد.

## قرارداد عمومی

گزینه‌ها زیر `profile.options` قرار می‌گیرند. کلیدهای خصوصی REALITY در
این قرارداد عمومی قرار ندارند و تغییر تنظیمات، هویت اینباند را عوض نمی‌کند.

```json
{
  "sniffing": {
    "enabled": true,
    "dest_override": ["http", "tls"],
    "metadata_only": false,
    "route_only": true,
    "domains_excluded": ["full:private.example.org"],
    "ips_excluded": ["192.0.2.0/24", "2001:db8::/32"]
  },
  "fallbacks": [
    {"dest": "8080", "xver": 0},
    {"path": "/status", "dest": "127.0.0.1:8081", "xver": 1}
  ]
}
```

### اعتبارسنجی Sniffing

- چهار مقدار `http`، `tls`، `quic` و `fakedns` پذیرفته می‌شوند؛ انتخاب تکراری
  پذیرفته نمی‌شود. وجود FakeDNS در فهرست، سرویس FakeDNS را نصب یا فعال نمی‌کند.
- هر فهرست استثنا حداکثر ۲۵۶ ردیف و هر ردیف حداکثر ۵۱۲ بایت دارد.
- استثنای دامنه می‌تواند متن ساده یا یکی از پیشوندهای `full:`، `domain:`،
  `keyword:` و `regexp:` باشد. عبارت منظم با قواعد RE2 در سرور بررسی می‌شود.
- استثنای IP شامل IP صریح یا CIDR است. فایل‌های GeoIP/GeoSite و منابع
  خارجی مدیریت‌نشده در این مرحله پذیرفته نمی‌شوند.
- ترتیب و متن معتبر ردیف‌ها حفظ می‌شود؛ اعتبارسنجی، حروف دامنه، نگارش IPv6
  یا قسمت میزبان یک CIDR را به‌شکل پنهان بازنویسی نمی‌کند.

`routeOnly` معمولاً نام تشخیص‌داده‌شده را فقط برای تصمیم مسیریابی استفاده
می‌کند؛ FakeDNS رفتار ویژهٔ Core را دارد. `metadataOnly` به معنی خواندن
نام دامنه از payload معمول HTTP/TLS نیست. استثنای IP نسبت به مقصد اولیه و
استثنای دامنه نسبت به نام تشخیص‌داده‌شده ارزیابی می‌شود.

### اعتبارسنجی Fallback

- فقط در انتقال TCP پروفایل فعلی VLESS/REALITY پذیرفته می‌شود؛ gRPC رد می‌شود.
- حداکثر ۳۲ ردیف؛ Path باید یکتا باشد، از جمله یک ردیف پیش‌فرض با Path خالی.
- Path خالی یا مسیری با `/` در ابتدا و حداکثر ۵۵ بایت است؛ فاصله، نویسهٔ
  کنترلی، query و fragment پذیرفته نمی‌شود.
- انتخاب Fallback با ALPN در REALITY نسخهٔ ثابت کار نمی‌کند؛ تست ترافیک
  واقعی روی مقصدهای پوششی HTTP/1.1 و HTTP/2 این رفتار را تأیید می‌کند.
  فیلد ALPN غیرخالی رد می‌شود و فرم کنترل قابل تنظیم برای آن ندارد.
- مقصد، پورت ۱ تا ۶۵۵۳۵ یا `host:port`/`IP:port` است؛ IPv6 با کروشه نوشته
  می‌شود. Unix socket و مقصدهای ویژهٔ `serve-*` خارج از این قراردادند.
- Xver فقط ۰، ۱ یا ۲ است؛ سرویس مقصد باید نسخهٔ انتخاب‌شدهٔ PROXY Protocol
  را پشتیبانی کند.

Fallback تنظیم Core برای هدایت اتصال است؛ failover نود یا مسیر Dark Swap
نیست. نسخهٔ ثابت Core، اتصال REALITY را نیز در handler مربوط باز می‌کند.
اما dependency ثابت REALITY، مقدار negotiated ALPN را در این مسیر handshake
تنظیم نمی‌کند. آزمون منفی، ردیف ALPN را فقط در کانفیگ خام fixture موقت تزریق
می‌کند و صفر بودن اتصال به مقصد آن را لازم می‌داند؛ محصول آن ورودی را قبول نمی‌کند.

## سازگاری مرورگر و داده

مرورگر باید هر بخش ذخیره‌شده را صریحاً بفرستد. حذف `sniffing` یا `fallbacks`
از ویرایش پروفایلی که آن بخش را دارد، تعارض است؛ حتی اگر مرورگر گزینه‌های
قدیمی REALITY/gRPC را فرستاده باشد. برای پاک‌کردن، `sniffing: {}` و
`fallbacks: []` لازم‌اند. `null` قصد پاک‌کردن را نشان نمی‌دهد. حضور این
فیلدها پیش از نرمال‌سازی ثبت می‌شود تا بررسی دوبارهٔ درخواست آن را از دست ندهد.

| محتوای نهایی پروفایل | قالب رمزگذاری‌شده |
| --- | --- |
| بدون گزینهٔ پیشرفته | نسخهٔ اصلی ۱ |
| فقط گزینه‌های REALITY/gRPC مرحلهٔ قبل | نسخهٔ ۲ |
| Sniffing دارای تنظیمات یا Fallback غیرخالی | نسخهٔ ۳ با AAD جدا |

باینری مرحلهٔ قبل نمی‌تواند پروفایل نسخهٔ ۳ را باز کند و فیلدهای ناشناخته را
بی‌صدا کنار بگذارد. خوانندهٔ جدید، JSON ناشناخته، کلید تکراری حتی با تفاوت
بزرگی حروف و دادهٔ اضافه را رد می‌کند. پاک‌کردن عمدی بخش‌های جدید با همان
کلید، قالب سازگار قدیمی‌تر را برمی‌گرداند. بازپخش درخواست، پاسخ تاریخی همان
رویداد را نگه می‌دارد، حتی اگر بعداً پروفایل ویرایش یا بازنشانی شده باشد.

پس از اولین ذخیرهٔ نسخهٔ ۳، برگشت به باینری فاقد این خواننده با داده سازگار
نیست. برگشت خودکار اولیهٔ نصب تنها پیش از ایجاد این پروفایل‌ها معتبر است.

## مرز اجرای واقعی

طرح‌های ساخت همچنان `runtime_apply: false` و متوقف‌اند. مسیرهای generic
ساخت/ویرایش اینباند فعال، Sniffing/Fallback غیرپیش‌فرض را نمی‌پذیرند؛ ایجاد
آن‌ها از آن مسیر می‌توانست در تحویل بعدی نود روی listener موجود اثر بگذارد.
حفاظت موجود طرح‌ها در برابر enable، تخصیص نود و اتصال مشتری حفظ می‌شود.

Fallback می‌تواند مستقیماً از داخل handler به مقصد وصل شود و از مانع
خروجی معمول حسابداری عبور کند. بنابراین admission مدیریت‌شده، Fallback
غیرخالی را رد می‌کند. تسویهٔ نهایی TCP و خروجی اشتراک آزمایشگاهی نیز دامنهٔ
محدود قبلی خود را حفظ می‌کنند و پشتیبانی authoring را مجوز اجرا تلقی نمی‌کنند.

آزمون loopback مستقل Core، معنی تنظیمات را با ترافیک واقعی بررسی می‌کند؛
این شاهد، مجوز فعال‌سازی روی نود یا اثبات حسابداری Fallback نیست.

### نتیجهٔ بررسی محلی

- مجموعهٔ کامل Go با Race و بررسی‌های متمرکز نهایی API/ذخیره موفق شدند.
- ساخت TypeScript/Vite، ۲۶۸ آزمون مرورگر بدون retry، و بازبینی فارسی/انگلیسی
  در عرض ۳۲۰ پیکسل موفق شدند. تغییر پایانی فاصلهٔ برچسب RTL نیز در سه مورد
  مرتبط دوباره بررسی شد.
- مرورگر واقعی به UI کامپایل‌شده، API احرازهویت‌شده و SQLite موقت وصل شد:
  ایجاد TCP با Sniffing/Fallback، بازکردن دوباره، خاموش‌کردن Sniffing با حفظ
  تنظیمات، حذف صریح Fallback، ویرایش به gRPC و حفظ هویت/رکوردهای نامرتبط موفق بود.
- Core رسمی `v26.9.9` با digest ثابت، ۳۰ کانفیگ topology را پذیرفت. تست‌های
  ترافیک با Race و UID/GID برابر ۶۵۵۳۴، هفت حالت Sniffing روی HTTP و Fallback
  پیش‌فرض/مسیر با PROXY نسخه‌های ۰، ۱ و ۲ را تأیید کردند.
- TLS/QUIC/FakeDNS در این مرحله پوشش سورس و syntax دارند؛ شاهد زندهٔ Sniffing
  مشخصاً HTTP است. آزمون منفی ALPN، صفر بودن اتصال به مقصد غیرقابل انتخاب را
  برای هر دو نوع مقصد پوششی HTTP/1.1 و HTTP/2 لازم می‌داند.
