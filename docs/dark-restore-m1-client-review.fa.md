# بازنشسته — Dark Restore M1

> این سند فقط سابقهٔ فنی است. UI، route و ابزار آن حذف شده‌اند و نباید دوباره
> نصب یا فعال شوند. مرز معتبر فعلی: [DARK-RESTORE-REMOVED.md](DARK-RESTORE-REMOVED.md).

## تغییر انجام‌شده در این مرحله

- منوی مستقل و تکراری «Dark Restore» از ناوبری حذف شده است.
- آدرس قدیمی `/dark-restore` به `/clients?view=restore` منتقل می‌شود. بازکردن بوکمارک قدیمی باید همان پنل بررسی را باز کند.
- فقط **مالک** در Clients بخش جمع‌شوندهٔ «Dark Restore — import review» را می‌بیند؛ نماینده هیچ کنترلی برای خواندن فایل بررسی ندارد.
- مرورگر فایل **JSON خصوصیِ بررسی** را محلی می‌خواند؛ SQLite قدیمی به HUB جدید آپلود نمی‌شود. هیچ تماس HTTP برای واردسازی، تغییر کاربر، اعتبار یا Node وجود ندارد.
- در پیش‌نمایش، کاربران، گروه‌ها، تعداد آرشیوی/ارتقایافته و مصرف تاریخی از دو Scope قدیمی با اعداد ده‌دهی دقیق نمایش داده می‌شوند. گروه آرشیوی از مجموع مصرف حذف نمی‌شود.
- مالک می‌تواند نگاشت پیشنهادی هر گروه یا همهٔ گروه‌ها به یک نماینده را انتخاب کند و **فایل نگاشت پیشنهادی** با SHA-256 منبع دریافت کند. این فایل *دستور اجرایی انتقال نیست*؛ `import_enabled=false` است.

## ورودی و سازگاری

کد، schema نسخهٔ مرجع قدیمی `darktunnelmika/dark-xray@ed66ded4ec09c9d023635f64d9b05eb592ce06a1` را با پیش‌بررسی M0 کنترل می‌کند.

فقط فایل SQLite مستقل و checkpoint‌شده بدون WAL/SHM/journal و بدون symlink، **پس از تأیید مشروعیت بکاپ توسط اپراتور** پذیرفته می‌شود. ابزار منبع را تغییر نمی‌دهد، به HUB قدیمی وصل نمی‌شود و قبل و بعد از بررسی SHA-256 را کنترل می‌کند. سقف M1 برای فهرست خصوصی ۵۰٬۰۰۰ کلاینت و ۸ GiB برای فایل مستقل است؛ تعداد بیشتر با دلیل مشخص رد می‌شود، نه اینکه صفحه‌ای از فایل را بی‌خبر جا بگذارد.

پیش‌بررسی M0 باید `ready_for_manual_review` باشد. در غیر این صورت هیچ برنامهٔ خصوصی ساخته نمی‌شود. برای هر کلاینت این نشانه‌ها جداست:

- `legacy_unlimited_requires_plan_policy`: حجم صفر در قدیم به معنی نامحدودِ حجم است؛ **با اعتبار نامحدود PRO یکسان فرض نمی‌شود**.
- `no_finite_expiry`: انقضای صفر، تاریخ خرید معتبر برای PRO نیست.
- `uuid_not_verified` / `duplicate_core_uuid`: از Xray Core شناسهٔ مطمئن پیدا نشده یا تکراری است؛ UUID جدید ساخته نمی‌شود.
- `source_disabled_do_not_reactivate`: قطع دستی/امنیتی قدیمی حفظ می‌شود.
- `archived_history_must_not_be_recreated_active`: سابقه و مصرف آرشیوی باید بماند و سرویس فعال حدسی ایجاد نشود.
- `promoted_identity_must_not_be_imported_twice`: کاربر قبلاً Promote شده و نباید دوباره وارد یا شارژ شود.
- `historical_counter_exceeds_signed_64bit`: شمارندهٔ خارج از محدودهٔ معتبر با صفر/MaxInt64 جایگزین نمی‌شود.
- `expired_requires_explicit_renewal`: کاربر منقضی خودبه‌خود تمدید نمی‌شود.

هیچ توکن، URL، Host، Email، Path، Query یا متن Core در خروجی بررسی ذخیره نمی‌شود. شناسهٔ کاربر و UUID در **JSON خصوصی** برای بررسی مالک باقی می‌مانند؛ از همین رو فایل باید مثل دادهٔ محرمانه نگهداری شود. ابزار CLI فقط شمارش، hash و وضعیت را روی stdout نشان می‌دهد.

## ساخت فایل بررسی در محیط آفلاین مستقل

ابتدا روی نسخهٔ مستقل و از قبل تأییدشده `sha256sum` بگیرید. سپس از سورس PRO، ابزار `./cmd/darkrestore-review` را کامپایل و روی **همان کپیِ مستقل** اجرا کنید:

```bash
darkrestore-review \
  -offline-copy-verified \
  -source /secure/offline/verified-old-hub.sqlite \
  -expected-sha256 '<SHA-256 of approved offline source>' \
  -as-of-unix '<Unix seconds of source snapshot time>' \
  -private-output /secure/offline/private-review.json
```

فایل خروجی باید **از قبل وجود نداشته باشد** و پوشهٔ والد آن خصوصی با مجوز 0700 باشد. فایل با 0600 ساخته می‌شود و تکرار درخواستِ ساخت همان فایل رد می‌شود. JSON باید پس از استفاده محافظت یا با سیاست حفظ شواهد حذف شود.

مرورگر داخل `Clients → Dark Restore`، گزینهٔ «بازکردن فایل خصوصی بررسی JSON» را دارد. آنجا می‌توانید گروه‌ها را به نماینده‌های موجود نگاشت کنید. **این مرحله هیچ واردسازی عملیاتی انجام نمی‌دهد و وضعیت محصول عمداً `import_enabled=false` می‌ماند.**

## تست‌ها و موارد پایان‌نیافته

- Go: بررسی ۵۱۷ کاربر مصنوعی، جمع دقیق مصرف، آرشیو/Promote، UUID تکراری یا غیرقابل‌تأیید، SHA اشتباه، جلوگیری از نشت توکن/URL و عدم ایجاد WAL.
- CLI: ساخت JSON خصوصی، جمع دقیق همهٔ Scopeها، refusal هنگام تکرار نام فایل و SHA اشتباه.
- Playwright: مسیر قدیمی، پیش‌نمایش مالکی، رد JSON دست‌کاری‌شده، محدودکردن به مالک و عدم ارسال درخواست نوشتن به HUB.
- **M2–M5 هنوز باقی‌اند:** پذیرش واقعیِ schema یک بکاپ مستقل، واردسازی با تراکنش و رسید idempotent، قرارداد تاریخچهٔ مصرف و اعتبار، درستی UUID/اشتراک، آرشیو و Promote، بازیابی پس از قطع، اتصال دقیق به نمایندگان و آزمون LAB. برای هیچ‌یک از این‌ها نباید از فایل M1 به‌عنوان مجوز Import استفاده شود.

تا پایان این مراحل هیچ مشتری واقعی، نماینده، بات، Node، دامنه یا پورت HUB قدیمی منتقل نمی‌شود. آزمون نهایی بازیابی بومی PRO روی دیتابیس ماندگار LAB نیز مستقل از Dark Restore باقی است.
